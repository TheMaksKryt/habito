# Habito

## О проекте

**Habito** — мобильное PWA-приложение для контроля питания, воды и основных показателей здоровья с социальной механикой совместного прогресса.

Главная идея проекта — создать не просто персональный фитнес-трекер, а дружелюбное приложение, в котором пользователи смогут следить за своими результатами вместе с друзьями, сравнивать прогресс, поддерживать друг друга и формировать полезные привычки.

Приложение должно иметь приятный мультяшный визуальный стиль, простой интерфейс и восприниматься не как медицинский инструмент, а как ежедневный помощник.

---

## Основные цели

- помочь пользователю контролировать количество выпитой воды;
- отслеживать употребление белка, калорий и других питательных веществ;
- формировать устойчивые привычки с помощью напоминаний;
- отображать понятную статистику за день, неделю и месяц;
- позволить добавлять друзей и совместно отслеживать прогресс;
- мотивировать пользователей через поддержку, серии успешных дней и совместные цели;
- предоставить удобное PWA-приложение, которое можно установить на телефон.

# Основные возможности

## Контроль воды

Пользователь сможет задать персональную дневную цель по воде, например 2 литра.

При настройке необходимо учитывать:

- желаемое количество воды в день;
- стандартный объём одного приёма воды;
- время пробуждения;
- время сна;
- период, в который разрешено отправлять уведомления;
- частоту напоминаний;
- уже выпитое количество воды.

На основе этих данных приложение должно автоматически распределять необходимое количество приёмов воды в течение активного времени пользователя.

### Пример

Пользователь должен выпить 2 литра воды, обычно пьёт по 250 мл и бодрствует с 08:00 до 23:00.

Приложение рассчитывает восемь приёмов воды и равномерно распределяет напоминания в течение дня.

### Возможности пользователя

- быстро отметить выпитую воду;
- выбрать объём конкретного приёма;
- посмотреть оставшееся количество воды;
- увидеть процент выполнения дневной цели;
- изменить дневную норму;
- изменить расписание сна;
- настроить тихие часы;
- посмотреть статистику за день, неделю и месяц.

Напоминания должны приходить на телефон через push-уведомления, в том числе когда приложение закрыто.

Для каждого продукта могут храниться:

- название;
- категория;
- стандартная порция;
- масса порции;
- калорийность;
- белки;
- жиры;
- углеводы;
- клетчатка;
- сахар;
- витамины;
- минералы;
- фотография продукта.

### Примеры продуктов

- яйцо;
- банан;
- куриная грудка;
- творог;
- протеиновый батончик;
- шаурма;

Пользователь указывает:

- продукт;

- время приёма пищи.

После сохранения приложение пересчитывает полученные питательные вещества и добавляет их в дневную статистику.

## Будущее AI-распознавание еды

После MVP пользователь сможет сфотографировать еду и отправить изображение на анализ нейросети.

Система должна попытаться определить:

- продукты на фотографии;
- примерный размер порции;
- ориентировочную калорийность;
- количество белков, жиров и углеводов;
- возможный состав блюда.

AI-результат не должен сохраняться автоматически.

Пользователь сначала получает предварительно распознанный список и может:

- изменить найденный продукт;
- удалить ошибочно определённый продукт;
- добавить пропущенный ингредиент;
- скорректировать массу порции;
- подтвердить результат.

Все значения, полученные по фотографии, должны быть помечены как приблизительные.

# Друзья и совместный прогресс

Социальная механика — одна из ключевых особенностей Habito.

У каждого пользователя будет уникальный код или ссылка-приглашение.

Другой пользователь сможет:

1. ввести код;
2. найти пользователя;
3. отправить запрос в друзья;
4. дождаться подтверждения.

После подтверждения друзья смогут видеть разрешённую статистику друг друга.

## Настройки приватности

Пользователь самостоятельно выбирает, какие данные доступны друзьям:

- процент выполнения нормы воды;
- количество выпитой воды;
- процент выполнения нормы белка;
- количество употреблённого белка;
- калории;
- изменение веса;
- серия успешных дней;
- общий дневной прогресс;
- список приёмов пищи.

Точные значения веса и подробный список еды должны быть скрыты по умолчанию.

## Сравнительная статистика

Для выбранного друга можно отображать:

- процент выполнения нормы воды;
- процент выполнения нормы белка;
- количество успешных дней;
- средний результат за неделю;
- текущую серию;
- общий процент выполнения целей;
- сравнительный график прогресса.

Сравнивать пользователей лучше по проценту выполнения их персональных целей, а не только по абсолютным значениям.

Например, прямое сравнение двух литров воды и трёх литров воды может быть некорректным, если у пользователей разные нормы.

## Социальные действия после MVP

- отправить реакцию;
- похвалить друга;
- отправить напоминание выпить воды;
- поддержать после пропущенного дня;
- создать совместную цель;
- начать недельный челлендж;
- собрать небольшую группу друзей.

# Альтернативы NestJS

## Elysia

Elysia подходит, если хочется использовать современный стек на Bun и получить лёгкий, быстрый и типобезопасный backend.

Преимущества:

- высокая производительность;
- современный API;
- хорошая TypeScript-интеграция;
- небольшой объём шаблонного кода.

Недостатки:

- более сильная зависимость от Bun;
- меньше готовых архитектурных соглашений;
- Clean Architecture и DI потребуется организовать самостоятельно;
- экосистема меньше, чем у NestJS.

## Hono

Hono — лёгкий framework, который может работать на Node.js, Bun, Deno и edge-платформах.

Преимущества:

- минимальный размер;
- простота;
- возможность edge-развёртывания;
- хорошая производительность.

Недостатки:

- структуру проекта необходимо проектировать самостоятельно;
- нет такого количества встроенных решений, как в NestJS;
- для большого модульного приложения потребуется больше собственной инфраструктуры.

## Рекомендуемый выбор

Для Habito основной выбор — **NestJS**.

Причины:

- модульная структура;
- встроенный Dependency Injection;
- guards, pipes, interceptors и decorators;
- удобная организация фоновых задач;
- хорошая поддержка WebSocket и очередей;
- понятная структура для дальнейшего роста проекта;
- соответствие выбранному подходу Clean Architecture.

Elysia можно рассматривать как экспериментальный вариант, а Hono — для небольшого API или edge-функций.

# ORM и база данных

## PostgreSQL

Основная база данных — PostgreSQL.

Она подходит для:

- связей между пользователями;
- истории показателей;
- статистики;
- продуктов и питательных веществ;
- запросов в друзья;
- челленджей;
- аналитических запросов.

## Prisma

Для MVP рекомендуется использовать Prisma.

Преимущества:

- понятная схема данных;
- типизированный клиент;
- миграции;
- удобная работа со связями;
- высокая скорость разработки.

Для сложной аналитики при необходимости можно использовать raw SQL.

Переход на другую ORM следует рассматривать только при появлении конкретных технических ограничений.

## Альтернатива — Drizzle

Drizzle можно выбрать, если потребуется:

- больше контроля над SQL;
- более тонкая абстракция;
- меньше runtime-магии;
- более прямое взаимодействие с PostgreSQL.

Для первой версии Prisma будет практичнее.

# AI-интеграция после MVP

AI-распознавание следует реализовать через абстракцию, которая не зависит от конкретного провайдера.

```ts
interface MealRecognitionProvider {
  recognize(image: UploadedImage): Promise<RecognizedMeal>;
}
```

## Предполагаемый процесс

1. Пользователь загружает фотографию.
2. Backend сохраняет файл в объектном хранилище.
3. Создаётся фоновая задача.
4. Изображение отправляется AI-провайдеру.
5. AI возвращает предполагаемые продукты и порции.
6. Backend сопоставляет результаты с внутренней базой.
7. Пользователь проверяет результат.
8. Пользователь корректирует данные.
9. После подтверждения создаётся приём пищи.

AI должен использоваться как помощник для ввода данных, а не как источник гарантированно точных медицинских сведений.

# Push-уведомления и расписание воды

Расписание воды рассчитывается на основе:

- дневной нормы;
- стандартного объёма приёма;
- времени пробуждения;
- времени сна;
- уже выпитой воды;
- текущего времени;
- часового пояса.

## Пример расчёта

```text
Дневная цель: 2000 мл
Размер приёма: 250 мл
Количество приёмов: 8
Период бодрствования: 08:00–23:00
```

Приложение должно равномерно распределить восемь приёмов воды в течение доступного периода.

При изменении данных расписание должно пересчитываться.

Например:

- пользователь выпил больше запланированного;
- пользователь пропустил напоминание;
- пользователь изменил время сна;
- пользователь временно отключил уведомления;
- пользователь начал день позже обычного.

# Безопасность и приватность

Приложение работает с персональными данными пользователя, поэтому приватность должна быть частью архитектуры.

## Основные требования

- данные пользователя закрыты по умолчанию;
- друг видит только разрешённую статистику;
- запрос в друзья требует подтверждения;
- точный вес скрыт по умолчанию;
- список еды скрыт по умолчанию;
- пользователь может удалить друга;
- пользователь может отозвать push-подписку;
- пользователь может удалить свои данные;
- доступ к файлам должен быть защищён;
- API должно проверять владельца каждого ресурса.

# Основная философия проекта

Habito должен помогать пользователю формировать привычки, а не наказывать его за ошибки.

## Принципы

- минимум действий для внесения данных;
- понятный ежедневный прогресс;
- спокойные напоминания;
- поддержка после пропущенных дней;
- добровольное социальное сравнение;
- приватность по умолчанию;
- сравнение по персональным целям;
- подтверждение AI-результатов;
- отсутствие медицинских обещаний;
- мобильный интерфейс как основной сценарий;
- постепенное усложнение продукта;
- бизнес-логика не должна зависеть от framework;
- архитектура не должна быть сложнее текущих потребностей проекта.

- формирования полезных привычек;
